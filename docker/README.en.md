## Running Services Using Docker-Compose

### Step 1: Modify the .env File

Copy `.env.example` from the project's root directory to the docker directory

```bash
cd docker
cp ../.env.example .env
```

> If you have specific requirements, please refer to the prompts in `.env.example` and adjust other configuration items accordingly. `JWT_SECRET`, `AI_INTERNAL_TOKEN`, and `CONFIG_CRYPTO_AES_KEY` are now automatically generated by the backend at startup and stored in the database (system_secrets table), so there is no need to configure them in .env.

```bash
# You can directly overwrite the default configuration in the env file with the following content
# ===== Database =====
PG_HOST=sino-website-postgresql
PG_PORT=5432
PG_DATABASE=sinounion
PG_USER=root
PG_PASSWORD=sinounion

# ===== Redis =====
REDIS_HOST=sino-website-redis
REDIS_PORT=6379
REDIS_PASSWORD=sinoredis

# ===== AI Service =====
PYTHON_HOST=sino-website-ai

# ===== Backend =====
BACKEND_HOST=0.0.0.0

# ===== Frontend =====
FRONTEND_PORT=3200
```

### Step 2: Run the Services

> If there is no local image, the source code will be built to create the image. If you want to quickly start using pre-built docker images, run `docker compose pull` first.

```bash
docker compose pull && docker compose up -d
```

### Viewing Logs

```bash
# Java backend logs
docker compose logs -f sino-website-backend

# Python backend logs
docker compose logs -f sino-website-ai

# Frontend logs
docker compose logs -f sino-website-frontend
```

### Updating to a New Version

```bash
# Pull the latest images
docker compose pull

# Start the services
docker compose up -d --force-recreate
```

### Building Docker Images from Source

> If building from the official source is slow, add the configuration `CN_MIRROR=true` in the .env file to switch npm/pip/maven to domestic mirrors

```bash
docker compose up -d --build
```
